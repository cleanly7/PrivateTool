## 1. 怎么跑、怎么验、什么绝对不能碰

项目：个人本机工具集。**没有账号、没有云、没有遥测，永远不做**。
技术栈：Next.js 15 App Router + React 19 + TypeScript + Electron 43 桌面壳 + 本地 SQLite（Node 内置 `node:sqlite` 的 `DatabaseSync`）。
现有侧栏：记账 / 冥想 / 专注时间 / 记录 / 喝水。**要做第六个：日程。**

```bash

npm run typecheck    # = tsc --noEmit
npm test             # = node --test lib/*.test.ts
npm run build        # 打包验证
npm run desktop      # Electron 桌面态
```

**三道门，每次改完都要全绿**：`npx tsc --noEmit` → `npm test` → `npm run build`。

**数据安全（最重要的一条）**

- 环境变量 `PRIVATE_TOOLBOX_DATA_DIR` 可覆盖数据目录。**任何测试、冒烟、造数据一律用 `/tmp/xxx`。**
- 用户的数据只有这一份，没有云备份。**破坏性迁移（重建表）前必须 `VACUUM INTO` 备份到数据目录。**

### 4.1 B2 · 删除记录后 8 秒内可撤销（✅ 已完成，留档给后续改动参考）

**做法**：`components/RecordsApp.tsx` 里点垃圾桶**不弹任何 confirm**，先把那一行从列表里拿掉，
同时起一个 `DELETE_UNDO_MS = 8000` 的定时器；**这 8 秒里一次网络请求都没发**，所以「撤销」只是
清掉定时器 + 把那条记录按 `started_at` 插回列表——记录从头到尾没被删过，不存在「恢复失败」。
8 秒到点才真正 `DELETE`；失败（非 404）会弹一条 `role="alert"` 的「删除失败，请重试」并把列表重新拉回来。

**为什么选「延迟 DELETE」而不是「先删再重新 POST」**：重新 POST 要重建 id、分心行、并处理
「POST 失败 = 用户数据真的没了」，而延迟删最坏情况只是记录留着。
**已知取舍（不是 bug）**：这 8 秒里退出应用/刷新页面，删除就不会发生了（记录留着）——数据安全优先；
如果是离开记录页（切到别的工具），`useEffect` 卸载钩子会立刻把这次删除落地（失败只 `console.error`，因为已经没有 UI 了）。

**同样在这一批里做完的**（第 3 章 A2 的后半句「事后在列表补原因/删条目」原来是**没做**的，现在真做了）：
- `lib/input.ts` 新增 `parseDistractionsPatch(value)`：`undefined` = 不动 → 返回 `undefined`；否则复用
  `parseDistractions`，非法返回 `null`（路由回 400「分心记录不合法」）；显式 `null` 当清空。
- `lib/db.ts` 的 `SessionUpdate` 加 `distractions?: DistractionInput[]`，`updateSession` 在同一个事务里
  「先按 `target_kind='session' AND target_id` 删旧行，再插新行」（**替换语义**，分心没有稳定 id）。
- `components/SessionNoteModal.tsx` 加分心编辑区（只有专注记录显示）：计数文案复用第 6 章的
  「这段分心了 N 次」/「这段没有记录到分心」，每行 = 时间 + 原因输入 + 删除按钮，class 复用
  `.focus-distractions` 系列。记录页的分心徽章从 `<span>` 改成 `<button>`，点它直接开这个弹窗。

**数据模型**

```sql
-- 只加表，不改表，所以不需要 VACUUM INTO 备份
CREATE TABLE IF NOT EXISTS categories (
  id TEXT PRIMARY KEY,                  -- 'tech' / 'japanese' / randomUUID()
  name TEXT NOT NULL,
  color TEXT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  archived INTEGER NOT NULL DEFAULT 0,  -- 停用标记，不物理删除
  created_at TEXT NOT NULL
);
-- 种子（幂等 INSERT OR IGNORE）：tech/技术学习/#2563eb, japanese/日语/#7c3aed

CREATE TABLE IF NOT EXISTS schedule_blocks (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL DEFAULT '',       -- ≤120
  category_id TEXT NOT NULL DEFAULT '', -- 引用 categories.id；'' = 未分类；不做外键
  started_at TEXT NOT NULL,             -- ISO UTC，归属日期看它（R5）
  completed_at TEXT NOT NULL,
  actual_seconds INTEGER,               -- 计时产生=真实秒数；手动添加=NULL
  note TEXT NOT NULL DEFAULT '',        -- ≤200
  source TEXT NOT NULL DEFAULT 'timer' CHECK (source IN ('timer', 'manual')),
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_schedule_blocks_started ON schedule_blocks (started_at);

CREATE TABLE IF NOT EXISTS time_distractions (
  id TEXT PRIMARY KEY,
  target_kind TEXT NOT NULL CHECK (target_kind IN ('session', 'schedule_block')),
  target_id TEXT NOT NULL,
  at TEXT NOT NULL,
  reason TEXT NOT NULL DEFAULT ''       -- ≤100
);
CREATE INDEX IF NOT EXISTS idx_time_distractions_target ON time_distractions (target_id);
```

**关键设计（每一句都是钱）**
- `categories.id` **直接沿用现在 `sessions.subject` 里存的字符串**（`'tech'` / `'japanese'`）。
  所以 **`sessions` 表里已有的数据一行都不用改，也不用重建表**。现在 `FOCUS_SUBJECTS`
  （`lib/types.ts`）是代码硬编码常量，迁移后它变成「这张表的前两行」，值完全一致。
- **空字符串 `''` 继续代表「未分类」，不作为表里的一行**。`FOCUS_UNCLASSIFIED` 的灰色继续由代码提供。
- `''` 是哨兵：**别把 `''` 变成真实 id**，那要重写所有历史行，收益为零。
- **`sessions` 表本模块一行都不改**：日程只**读**它（`isFocusKind` 的），通过 A5 的 PATCH 接口**写**它。
- 显示时长统一 `actual_seconds ?? (completed_at - started_at)`；**不能用后者覆盖前者**——中途暂停过，两者不相等。
- **没有 `planned_minutes` 这类折算列**（R11）。
- `time_distractions` **没有外键**，所以删会话 / 删日程块时**必须显式级联删**对应分心行，且**必须带 `target_kind` 条件**。
- 分类**停用不能删行**（`archived=1`），否则历史块的颜色会丢。
- 新增 localStorage：`schedule-timer-draft`、`schedule-timer-pending`，结构与 `CountUpDraft` / `PendingSave` 同构。
  **这两处会原样重演第 5 章的 T1 和 T2，设计时必须一次性做对。**

**分期（按顺序做，不要跳）**
1. **Phase 1 · 全局分类表**：纯重构，解锁自定义分类。种子数据 + 读写函数。

## 5. 陷阱清单（不加处理就会踩，每条都真实发生过）

- **T1｜「保存失败 → 刷新 → 重试」会静默丢字段。**
  待保存结构（`PendingSave`）与 `pendingToPayload` 必须同步携带 `title` 和 `distractions`。
  加任何新字段都要同时改三处：结构定义、解析函数、回传请求体的函数。**已修，别改坏。**
- **T2｜改本地草稿结构会吃掉用户正在跑的计时。**
  读取草稿的版本校验**不能**写成「必须等于当前版本」，否则老草稿被判无效直接丢弃。
  正确做法：维护一个「可读版本列表」，把老版本补默认值后统一升级成新结构，并用单测钉住一个老版本样例。**已修，别改坏。**
- **UTC 陷阱**：构造某一天的日期**必须**用 `new Date(year, month - 1, day)` 本地构造。
  写 `new Date("2026-05-11")` 会被当成 UTC 解析，东八区会**退成前一天**。周/日推进一律用 `lib/date.ts` 的 `startOfLocalWeek` / `addLocalDays`。
- **`PATCH /api/sessions/{id}` 要求请求体里的 `note` 必须是字符串**，否则一律 400「备注格式不正确」。
  所以**只传 `actual_seconds` 或只传 `title` 的 PATCH 会失败**——调用方必须总是带上 `note`。
- **`PATCH` 的 `distractions` 是「整批替换」语义**：字段缺省 = 一条都不动；传 `[]` = 清空；传数组 = 先删该 session
  的全部旧行再插新行（所以分心行的 `id` 每次保存都会变，**不要**拿 `id` 当 React key 或做增量对比，
  分心的身份是 `at`）。路由只对 `isFocusKind` 的记录传这个字段，冥想法传了也会被丢掉。
  改动分心必须**同时带上 `note`**，理由同上一条。
- **`kind` 是 `CHECK` 约束列**：加新字典值必须重建整张表。`time_distractions.target_kind` 已经把
  `'schedule_block'` **提前写进 CHECK**了，就是为了省一次重建——不要删掉那个值。
- **`lib/*.ts` 之间互相 import 必须带 `.ts` 后缀**（`import { x } from "./types.ts"`）；
  **组件/路由里用 `@/lib/xxx`（不带后缀）**。两套写法并存，混用就是 `ERR_MODULE_NOT_FOUND`。
- **`node --test` 直接跑 `.ts` 源文件**：纯逻辑里不要用 Next 专属 API。
- **`setInterval` 只用于触发重渲染**，计时值必须由 `elapsedMs(...)` 现算，否则会出现「后台标签页少算时间」。
- **`AppShell` 的工具选择不刷新持久化**，刷新回到「记录」；用无头浏览器验证时每次都要重新点侧栏。
- **localStorage 草稿会跨测试轮次污染**：调试计时前先 `localStorage.clear()`。
- **不要改 `isFocusKind`**（`kind === "focus" || kind === "pomodoro"`），不要把 `planned_minutes` 当真实时长用。

## 7. 交接要求

1. **提交粒度**：一个批次一个 commit，中文 message 且说明「为什么」，与仓库现有风格一致。
2. **文档回写**：改完把 `README.md` 里对应用户说明同步好。
3. **必须补的单测**：老草稿兼容（v2 → 新结构）、`PendingSave` 带 `title`/`distractions` 的往返、
   `parseSessionInput` 对 `distractions` 的边界、`parseDistractionsPatch`（`undefined` 不动 / `null` 与 `[]` 清空 / 非法返回 `null`）、
   `updateSession` 同步 `planned_minutes` 与**整批替换分心**（不传保留、传 `[]` 清空、替换后不留旧行）、
   `formatCompact` 的边界值、总览的空数组/平局取更早/跨年边界。
4. **不允许**：为了让测试变绿而放宽校验、删掉断言、或把失败路径改成静默。
5. **收尾**：临时目录、冒烟库、后台 dev server / 浏览器进程全部收掉；
   确认真实库没被测试改动过（对比 sha256）。
